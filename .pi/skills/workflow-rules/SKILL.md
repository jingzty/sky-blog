# 项目协作约定（sky-blog2）

以下约定在本项目长期有效，无论会话是否续接、summary 是否保留，都必须遵守。

## Git 推送约定

- **未经用户明确指示，绝不执行 `git push`**（或任何把提交推到远程的命令）。
- 用户说「推送」「push」「推一下」等明确指令时才推送；推送命令统一用
  `git push origin main:sky-blog2`（本项目固定推到 sky-blog2 分支）。
- 每次 `git commit` 完成后，**只能问**「要推送吗？」，绝不在提交命令里顺手拼 push、
  也不要在未经确认时自动推送。
- 本地 commit 不受此限制——可以按需 commit，只是不能 push。

## 数据库凭据保护约定

- **测试需要鉴权的接口时，绝不修改数据库里的真实 `adminPassHash`**。
  （`adminPassHash` 是 sha256 单向哈希，一旦被覆盖原值永久丢失，不可逆，
  无法靠"恢复"找回——历史事故已证明此做法会直接导致用户登录不上。）
- 需要登录拿 token 时，二选一：
  1. 用环境变量临时起账号：`ADMIN_USER=xxx ADMIN_PASS=yyy node server.js`
     （环境变量优先级高于数据库，不污染库内凭据，测试结束重启即复原）；
  2. 直接 cookie/token 注入：服务端 `reqToken` 同时接受 `admin_token` cookie
     与 `Authorization` 头，可用 Playwright `ctx.addCookies` 注入，
     根本不用登录、不用碰凭据。
- 绝不采用"改数据库凭据 → 测试 → 改回"这套做法，哪怕是"临时"也不行：
  单向哈希没有"还回去"，只有"覆盖"，且"恢复"时任何复制粘贴/肉眼比对误差
  都会造成不可逆损坏（如哈希末尾被截断成 54 位仍肉眼难察）。
- 任何对关键数据的写回，必须做字节级校验（`length === 64`、逐字节比对），
  不能只凭"看起来字符串一样"就认为成功。

## 编辑改动守约

- **改代码必须守住"要保留的旧内容"**：用 `edit` 做替换时，`newText` 里必须把
  未被要求修改的旧属性/旧字段/旧逻辑原样写全，不能只写"新增/修改的部分"。
  错误示范：原规则是 `{ color:#fff; font-size:0.86rem; ... }`，为改字号把整条替换成
  `@media(...) { .x { font-size:0.96rem; } }`，结果 `color:#fff` 等旧属性全丢。
  正确做法：`newText` 里先完整保留原规则，再追加 `@media` 块覆盖字号。
- **改完必须校验关键属性/字段未丢失，再交付**：涉及 CSS/配置/接口字段等改动，
  改完用脚本（Playwright 读 `getComputedStyle`、或读 DB/接口返回）核实"不该变的
  没变"——比如改字号后要校验 `color` 仍是原值、改某字段后要校验其他字段仍在。
  不能只凭"我没动它"就假定它还在，必须客观验证。
- **不靠肉眼和记忆判断"没改坏"**：连续出现"改密码把原哈希丢掉"、"改字号把
  `color:#fff` 丢掉"这类事故，根因都是"我以为没动那部分"。任何"只改一小处"的
  改动，都以"实际渲染/存储结果"为准，不以"我编辑时的意图"为准。
- 交付前自检清单（CSS 类改动适用）：
  1) 没有删掉未被要求改的属性（color/opacity/line-height 等）；
  2) 用脚本读计算样式，确认未要求变的属性值与改前一致；
  3) 截图/读值确认改动只在目标范围生效（如"只 web 端"改动不影响移动端）。
